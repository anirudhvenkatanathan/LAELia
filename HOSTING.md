# Hosting LAELia

**Live stack:** Render (one Node web service, defined in `render.yaml`) and MongoDB Atlas.

The API serves `/api/*` and `/graphql`, and the built React app is served from the same URL.

## Change workflow
1. Each change goes on a feature branch and gets a pull request.
2. The PR is built, tested and reviewed, with screenshots.
3. When it's approved, it's merged into `main`. Render deploys `main` automatically.

## Environment variables (set in Render, never committed)
| Key | Purpose |
|---|---|
| `MONGO_URI` | Atlas connection string ending in `/claim_triage` |
| `ANTHROPIC_API_KEY` | Used by the AI claim summary and vendor intelligence features |
| `JWT_SECRET` | Auto-generated by Render |
| `SEED_ON_EMPTY` | `true` loads `seed/ClaimDB` on startup, but only if the database has no login users |

## Known limitations on the free plan
- **Sleeping:** the service sleeps after 15 min idle, so the first request after that takes about 30–60 s.
- **Uploaded vendor documents are not kept:** they're written to `/tmp` and lost on each restart or deploy. For permanent storage, move to the Starter plan and add a Render Disk mounted at e.g. `/var/data`. Then set `VENDOR_DOC_UPLOAD_PATH=/var/data/vendor_doc_uploads`.

## Local development
1. Copy `.env.example` to `sourceCode/apps/api/.env` and to `.env` at the repo root, then fill in the values.
2. Run the API: `cd sourceCode/apps/api && npm ci --legacy-peer-deps && npm run dev`.
3. Run the frontend: `cd sourceCode/apps/frontEnd && npm ci && npm run dev`.
